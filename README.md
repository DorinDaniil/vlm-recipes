# vlm-recipes

Дообучение открытых LLM/VLM под агентные задачи: SFT (LoRA и варианты),
выравнивание по предпочтениям (DPO, ORPO, SimPO, KTO), управление
поведением через векторы активаций, вызов инструментов. Целевая модель
в примерах — Qwen3.5-9B; код к семейству не привязан.

## Структура

    books/        теория, PDF; исходники в books/tex
    notebooks/    эксперименты, один метод на ноутбук
    data/         учебные наборы; data/task — наборы под задачу компании
    tools/        проверка модели, данных, окружения
    docs/         бенчмарки
    vlmkit/       коллатор, генерация, парсер вызовов, инструменты, совместимость версий

## Установка

    pip install -r requirements.txt

`torch` устанавливается отдельно под версию CUDA, поддерживаемую
драйвером.

Проверка модели и данных:

    python tools/check_model.py Qwen/Qwen3.5-9B
    python tools/selfcheck.py

## Ноутбуки

Три учебных сценария с нарочно утрированным поведением: эффект виден
без метрик, а контрольная группа проверяет, что выучилось правило
«когда», а не только «как». Каждый ноутбук загружает модель, измеряет
поведение до вмешательства, применяет метод, измеряет после на тех же
шести запросах.

| | метод | сценарий |
|---|---|---|
| `00-data` | — | что в данных, как устроены детекторы и замер, базовая линия |
| `01-sft` | LoRA | мат в ответах о выпускной работе, нейтрально обо всём остальном |
| `02-steering` | вектор активаций | отказ от любого запроса; сила вектора развёрткой |
| `03-dpo` | ORPO / DPO / SimPO / KTO | сценарий `01` на парах «лучше / хуже» |
| `04-tools` | LoRA, цикл с настоящими функциями | `calc`, `word_count`, `reverse`: итог сверяется с известным ответом |
| `05-compare` | LoRA, rsLoRA, DoRA | сценарий `01`, сводная таблица |
| `06-chat` | — | свои промпты к адаптеру и/или вектору: полный промпт, потоковый ответ без обрезки |

Вызовы `peft`, `transformers`, `trl` в ячейках без обёрток.

## Данные

| файл | n | поля | группы |
|---|---|---|---|
| `swear.jsonl` | 88 | question, plain, swear | topic / other |
| `refusal.jsonl` | 40 | prompt, comply, refuse | topic / other |
| `tools.jsonl` | 116 | messages, expected | tool / multi / direct |

Метрика везде пара recall / FPR: доля целевой группы, где детектор
сработал, и доля контрольной, где сработал зря. Рядом стандартные
величины: perplexity целевых ответов, preference accuracy и margin,
совпадение вызова с эталоном как в BFCL, pass@1 полного цикла.
Детекторы — регулярные выражения в `notebooks/common.py`. Чётные
строки идут в обучение, нечётные — в замер.

`tools.jsonl` генерируется `data/build_tools.py`: инструменты
исполняются при сборке, результаты в траекториях верные, в поле
`expected` лежит то, что должно оказаться в конечном ответе агента.
Формат вызова (`STYLE`) должен совпадать с шаблоном модели; проверяется
`tools/selfcheck.py`.

`data/task/` — наборы под задачу компании в том же формате:
`policy.jsonl` (143, clarify / guide / answer), `tools.jsonl` (66,
инструменты из ТЗ), `prefs.jsonl` (60), `skills.jsonl` (49). Гоняются
теми же ноутбуками; набор для замера — `policy_suite()` в `common.py`.

## vlmkit

- `data` — `Sample`, `ChatCollator` (маскирует промпт, описание и
  результаты инструментов, блок `<think>`), `preview`
- `evaluate` — генерация с left padding и выключенным рассуждением;
  `Suite` с матрицей ошибок (recall, FPR, precision, F1); `perplexity`,
  `preference_accuracy`, `matches_reference_call`
- `toolcalls` — разбор `<tool_call>` в JSON и XML
- `toytools` — `calc`, `word_count`, `reverse`, `roll_dice`; схема
  для шаблона и исполнение разобранных вызовов
- `steering` — `SteeringVector`: разность средних активаций, единица
  силы — сама разность
- `compat` — фильтр аргументов `TrainingArguments`, поиск тренеров TRL
  по версии (в trl 1.x ORPO и CPO лежат в `trl.experimental`)
- `model`, `chat`, `guardrails` — загрузка, диалог, фильтрация запросов
