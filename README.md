# vlm-recipes

Дообучение открытой LLM под продуктовую задачу: ассистент студента,
пишущего выпускную работу в редакторе. Перед агентом стоит отдельная
модель фильтрации запросов, которая решает, пропускать запрос или нет.
Агент работает с тем, что прошло фильтр: выбирает навык вызовом
`select_skill`, а затем отвечает по правилам продукта — содержательные
решения оставляет студенту, опирается только на открытый документ,
правки формы предлагает к принятию, заканчивает одним шагом. Вторым
эшелоном агент коротко отказывает, если нарушение всё же прошло фильтр.

Методы: SFT (LoRA), выравнивание на парах (DPO, ORPO, SimPO, KTO),
вектор управления. Модель в примерах — Qwen3.5-9B; код к семейству
не привязан.

## Структура

    books/        теория, PDF; исходники в books/tex
    notebooks/    эксперименты, один метод на ноутбук
    data/         голд-сет продукта, обучение, навыки, документы
    tools/        проверка модели, данных, автопроверок, маскирования
    docs/         концепт целиком и бенчмарки
    vlmkit/       коллатор, навыки, автопроверки, метрики по логитам, совместимость версий

## Установка

    pip install -r requirements.txt

`torch` устанавливается отдельно под версию CUDA, поддерживаемую
драйвером. Проверки:

    python tools/check_model.py Qwen/Qwen3.5-9B   # пригодна ли модель к дообучению
    python tools/check_data.py                    # данные: структура и разметка
    python tools/audit_checks.py                  # различают ли автопроверки
    python tools/selfcheck.py                     # маскирование в коллаторе

## Данные

**Тест продукта** — голд-сет, `data/golden.jsonl`: 36 ситуаций в шести
категориях (рецензия и правки текста, литература, методы и эмпирика,
маршрут работы, замечания руководителя, элементы введения). У каждой —
запрос студента, открытый фрагмент документа, рубрика PASS/FAIL из трёх
пунктов, ответ продового агента с вердиктами судьи и человека,
эталонный ответ и заведомо плохой. Не меняется и в обучение не входит.

**Обучение** — `data/train/*.jsonl`, 257 ситуаций в 15 файлах:
214 в обучении и 43 в своей отложенной выборке (`split = "dev"`).
Она нужна вторым замером: в голд-сете 36 ситуаций и два навыка
представлены одним примером, а dev покрывает все шесть. Документов 31,
из них 26 только в обучении, пятнадцать предметных областей; документы
теста и обучения не пересекаются.

Каждая ситуация несёт запрос, документ, историю, ожидаемый навык,
эталонный ответ, плохой ответ и назначенные автопроверки, поэтому одни
и те же строки идут в SFT, в пары для выравнивания и в вектор.

| | |
|---|---|
| 26 ситуаций | `route = "guard"`: явные нарушения честности, которые отсекает фильтр запросов; агент вторым эшелоном коротко отказывает |
| 25 ситуаций | легитимные запросы, похожие на нечестные: перефразировать свой текст, проверить свой расчёт, разобрать отчёт антиплагиата |
| 13 ситуаций | содержательные решения студента: тема, цель, гипотеза, задачи, объект и предмет |
| 56 ситуаций | многоходовые: студент ответил на вопрос, принёс свою формулировку, спорит с замечанием; в 18 из них три хода со сменой навыка |
| 32 ситуации | с пустым документом: проверяют, что модель не выдумывает его содержимое |

Роли не смешаны намеренно: отказы собраны в `blocked.jsonl`, а рядом
стоят похожие на них легитимные запросы. Если учить отказам вперемешку
с обычной работой, растут ложные отказы.

Ответы написаны обычным текстом, без заголовков и жирного выделения.
Что покрывает каждый файл и зачем — [docs/overview.md](docs/overview.md).

`data/skills.json` — шесть навыков: текст методики, который получает
модель после `select_skill`. `data/documents.json` — фрагменты
документов.

## Метрики

Формулы и разбор — в `00-data`, замер идёт на голд-сете и на dev.

| метрика | что считает |
|---|---|
| skill_called / skill_acc | инструмент вызван вообще; вызван с верным навыком |
| completed | цикл завершился ответом, а не повторным вызовом |
| checks_all / checks_mean | все автопроверки выполнены; средняя доля выполненных |
| block_recall | отказ на ситуациях `route = "guard"` — работает ли второй эшелон |
| decline_fpr | ответ начинается с отказа там, где отказывать не нужно |
| judge_pass | вердикт LLM-судьи по рубрике голд-сета; согласие с вердиктами команды измеряется отдельно |
| perplexity, preference accuracy | вероятность эталонов и пар на отложенных ситуациях |

Доли идут с доверительным интервалом Уилсона: на 36 ситуациях он
шириной около 15 процентных пунктов, и без него разницу в две-три
ситуации легко принять за эффект.

Автопроверки — `vlmkit/rubric.py`, стандартная библиотека. Их
разделяющая способность измеряется отдельно:

    python tools/check_data.py     # структура данных, пересечения, разметка
    python tools/audit_checks.py   # различает ли каждая проверка хороший ответ от плохого

Сейчас все 293 эталона проходят свои проверки, а из 293 плохих
ответов — только 7: их нарушение содержательное, и ловит его судья.
Разбор по каждой проверке — в [docs/overview.md](docs/overview.md).

## Ноутбуки

| | что делает |
|---|---|
| `00-data` | голд-сет с полными примерами, вердикты продукта, метрики с формулами, судья против человека, базовая линия на голд-сете и dev |
| `01-sft` | LoRA на траекториях «запрос → select_skill → навык → ответ»; до/после, полные ответы |
| `02-steering` | вектор «решение остаётся за студентом» из пар эталон/плохой; развёртка по силе |
| `03-dpo` | ORPO / DPO / SimPO / KTO на парах, при желании поверх SFT-адаптера; preference accuracy |
| `04-compare` | все сохранённые варианты в одной таблице, ответы рядом |
| `05-chat` | свои запросы с документом к любому варианту; полный промпт, потоковый ответ |

Вызовы `peft`, `transformers`, `trl` в ячейках без обёрток.

## vlmkit

- `data` — `Sample`, `ChatCollator` (маскирует запрос, описание и
  результаты инструментов, блок `<think>`), `preview`
- `skills` — схема `select_skill` и подстановка текста навыка
- `rubric` — автопроверки ответа
- `evaluate` — `perplexity`, `preference_accuracy`, left padding
- `toolcalls` — разбор `<tool_call>` в JSON и XML
- `steering` — `SteeringVector`
- `compat` — фильтр аргументов, поиск тренеров TRL по версии
- `model` — процессор и очистка видеопамяти

Системный промпт, сборка ситуации, агентский цикл, метрики и печать —
`notebooks/common.py`.
