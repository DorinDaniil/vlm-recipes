# vlm-recipes

Дообучение открытой LLM под продуктовую задачу: ассистент студента,
который пишет выпускную работу в редакторе. Модель выбирает навык
вызовом `select_skill`, затем отвечает по правилам продукта:
содержательные решения оставляет студенту, опирается только на открытый
фрагмент, правки формы предлагает к принятию, заканчивает одним шагом.

Методы: SFT на LoRA, выравнивание на парах DPO, ORPO, SimPO, KTO,
вектор управления. Модель в примерах Qwen3.5-9B, код к семейству
не привязан.

Концепт целиком, устройство данных и смысл метрик —
[docs/overview.md](docs/overview.md).

## Структура

    books/        теория, PDF; исходники в books/tex
    notebooks/    эксперименты, один метод на ноутбук
    data/         голд-сет продукта, обучение, навыки, документы
    tools/        проверки без GPU
    docs/         концепт и бенчмарки
    vlmkit/       коллатор, навыки, автопроверки, метрики по логитам, совместимость версий

## Установка

    pip install -r requirements.txt

`torch` ставится отдельно под версию CUDA, поддерживаемую драйвером.

## Проверки

    python tools/check_data.py     # состав данных, разметка, пересечения
    python tools/audit_checks.py   # различают ли автопроверки хороший ответ от плохого
    python tools/selfcheck.py      # маскирование в коллаторе
    python tools/check_model.py Qwen/Qwen3.5-9B   # пригодна ли модель к дообучению

Первые три идут на стандартной библиотеке, без torch и GPU.

## Ноутбуки

| | что делает |
|---|---|
| `00-data` | данные с полными примерами, метрики с формулами, судья, базовая линия |
| `01-sft` | LoRA на траекториях «запрос → select_skill → навык → ответ» |
| `02-steering` | вектор «решение остаётся за студентом», развёртка по силе |
| `03-dpo` | ORPO, DPO, SimPO, KTO на парах, при желании поверх SFT-адаптера |
| `04-compare` | все сохранённые варианты в одной таблице, ответы рядом |
| `05-chat` | свои запросы с документом к любому варианту |

Вызовы `peft`, `transformers`, `trl` в ячейках без обёрток.
